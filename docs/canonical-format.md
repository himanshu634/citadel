# Canonical JSONL format

The `canonical_jsonl` source type ingests any tool's data without Python: export it, convert
it to these files (one JSON object per line) and point a company config at the folder:

```yaml
sources:
  - type: canonical_jsonl
    path: data/inbox/<slug>/jsonl     # repo-root relative
```

Every file is optional. Every line is validated against `apps/brain/brain/canonical.py`; a bad
line stops ingestion with its file and line number. Timestamps are ISO 8601 (`2026-05-01T12:00:00Z`;
a missing zone means UTC). Text fields are scrubbed of email addresses on the way in. People
are referenced by login everywhere (`author_login`, `reviewer_login`), never by email.

Fields every record accepts: `uid` (stable id; re-ingesting the same uid updates the node),
`source` (defaults to `canonical_jsonl`; e.g. `slack_export`), `url` (shown as the citation).

Working example: [`apps/brain/examples/synthetic_company/`](../apps/brain/examples/synthetic_company/)
(generated by `generate.py` there).

## `people.jsonl` → Person

uid is derived (`person:<login>`, lower-case) when left out. No email field exists, by design.

| field | type | required |
|---|---|---|
| `login` | str | yes |
| `display_name` | str (optional) |  |
| `is_bot` | bool |  |

```json
{"display_name": "Alice Kim", "login": "alice"}
{"display_name": "Bob Ortiz", "login": "bob"}
{"display_name": "Carol Singh", "login": "carol"}
```

## `teams.jsonl` → Team

uid is derived (`team:<name>`) when left out.

| field | type | required |
|---|---|---|
| `name` | str | yes |

```json
{"name": "identity"}
{"name": "payments"}
```

## `systems.jsonl` → System

Optional: systems are normally derived from file paths via `systems.rules`. uid is derived (`system:<name>`).

| field | type | required |
|---|---|---|
| `name` | str | yes |
| `path_rule` | str (optional) |  |

```json
{"name": "Billing", "path_rule": "services/billing/**"}
```

## `work_items.jsonl` → WorkItem

PRs, issues, tickets and chat threads share this shape; `kind` tells them apart.

| field | type | required |
|---|---|---|
| `kind` | `pull_request` / `issue` / `ticket` / `thread` | yes |
| `number` | int (optional) |  |
| `title` | str | yes |
| `body` | str |  |
| `state` | str | yes |
| `created_at` | datetime | yes |
| `updated_at` | datetime (optional) |  |
| `closed_at` | datetime (optional) |  |
| `merged_at` | datetime (optional) |  |
| `author_login` | str (optional) |  |
| `labels` | list[str] |  |
| `container` | str (optional) |  |
| `key` | str (optional): the tracker's human id, e.g. `ENG-123` |  |
| `status_category` | `backlog` / `todo` / `in_progress` / `done` / `canceled` (optional) |  |
| `priority` | `urgent` / `high` / `medium` / `low` (optional) |  |
| `due_date` | date, `2026-06-30` (optional) |  |
| `assignees` | list[str] of logins (optional) |  |

`state` keeps the tracker's own word ("In Review"); `status_category` is the same status in
one shared vocabulary. A work item with a `status_category` other than `done` / `canceled` is an
open ticket: normalize keeps it even when it is older than `window.since`.

`assignees` tells "not tracked" from "nobody": leave it out (null) when the source has no
assignees, use `[]` when the item is unassigned. Entries are logins, never emails, and go
through `people.aliases` like every other login.

```json
{"author_login": "alice", "body": "We decided to replace server-side sessions with short-lived JWTs because the session table was the main source of DB load. Refresh tokens stay server-side. Closes #11.", "closed_at": "2026-02-06T12:00:00Z", "container": "synthetic/app", "created_at": "2026-02-03T12:00:00Z", "kind": "pull_request", "merged_at": "2026-02-06T12:00:00Z", "number": 1, "state": "merged", "title": "feat(auth): switch sessions to JWT", "uid": "synthetic:pr:1", "url": "https://example.com/synthetic/app/pull/1"}
{"author_login": "alice", "body": "Two tabs refreshing at once could revoke each other.", "closed_at": "2026-03-12T12:00:00Z", "container": "synthetic/app", "created_at": "2026-03-10T12:00:00Z", "kind": "pull_request", "merged_at": "2026-03-12T12:00:00Z", "number": 2, "state": "merged", "title": "fix(auth): refresh token rotation race", "uid": "synthetic:pr:2", "url": "https://example.com/synthetic/app/pull/2"}
{"author_login": "bob", "body": "Prorate by day, not by hour; finance confirmed day granularity is enough. Touches the plan picker in web/ too. Closes #12.", "closed_at": "2026-03-09T12:00:00Z", "container": "synthetic/app", "created_at": "2026-03-02T12:00:00Z", "kind": "pull_request", "merged_at": "2026-03-09T12:00:00Z", "number": 3, "state": "merged", "title": "feat(billing): proration for plan changes", "uid": "synthetic:pr:3", "url": "https://example.com/synthetic/app/pull/3"}
```

## `changes.jsonl` → Change

`files` are mapped to systems by the company's path rules. Leave `kind` empty to parse it from a conventional-commit subject (`fix(x): ...`). `touches` is filled by normalize; do not set it.

| field | type | required |
|---|---|---|
| `sha` | str | yes |
| `date` | datetime | yes |
| `author_login` | str (optional) |  |
| `subject` | str | yes |
| `kind` | `feat` / `fix` / `perf` / `ci` / `build` / `docs` / `refactor` / `other` (optional) |  |
| `files` | list[str] |  |
| `systems` | list[str] |  |
| `touches` | dict[str, list[str]] |  |

```json
{"author_login": "alice", "date": "2026-02-04T12:00:00Z", "files": ["services/auth/jwt.py"], "sha": "a001", "subject": "feat(auth): add JWT issuer", "uid": "synthetic:commit:a001", "url": "https://example.com/synthetic/app/commit/a001"}
{"author_login": "alice", "date": "2026-02-05T12:00:00Z", "files": ["services/auth/session.py", "services/auth/jwt.py"], "sha": "a002", "subject": "feat(auth): drop session table usage", "uid": "synthetic:commit:a002", "url": "https://example.com/synthetic/app/commit/a002"}
{"author_login": "alice", "date": "2026-02-05T12:00:00Z", "files": ["services/auth/login.py", "web/login/page.tsx"], "sha": "a003", "subject": "feat(auth): login page uses JWT", "uid": "synthetic:commit:a003", "url": "https://example.com/synthetic/app/commit/a003"}
```

## `reviews.jsonl` → Review

Becomes `(Person)-[:REVIEWED {state}]->(WorkItem)`; the latest review per person and work item wins.

| field | type | required |
|---|---|---|
| `work_item_uid` | str | yes |
| `reviewer_login` | str | yes |
| `state` | str | yes |
| `submitted_at` | datetime | yes |

```json
{"reviewer_login": "carol", "state": "APPROVED", "submitted_at": "2026-02-06T12:00:00Z", "uid": "synthetic:review:1:carol:2026-02-06", "url": "https://example.com/synthetic/app/pull/1", "work_item_uid": "synthetic:pr:1"}
{"reviewer_login": "dave", "state": "COMMENTED", "submitted_at": "2026-02-05T12:00:00Z", "uid": "synthetic:review:1:dave:2026-02-05", "url": "https://example.com/synthetic/app/pull/1", "work_item_uid": "synthetic:pr:1"}
{"reviewer_login": "carol", "state": "APPROVED", "submitted_at": "2026-03-12T12:00:00Z", "uid": "synthetic:review:2:carol:2026-03-12", "url": "https://example.com/synthetic/app/pull/2", "work_item_uid": "synthetic:pr:2"}
```

## `comments.jsonl` → Comment

Becomes `(Person)-[:COMMENTED_ON {count, last_at}]->(WorkItem)` plus a text `Chunk` FROM the work item.

| field | type | required |
|---|---|---|
| `work_item_uid` | str | yes |
| `author_login` | str | yes |
| `created_at` | datetime | yes |
| `body` | str | yes |

```json
{"author_login": "dave", "body": "Does this remove the sessions table entirely? Ops wants it gone.", "created_at": "2026-02-05T12:00:00Z", "uid": "synthetic:comment:1", "url": "https://example.com/synthetic/app/pull/1#comment-1", "work_item_uid": "synthetic:pr:1"}
{"author_login": "alice", "body": "Yes after one release; refresh tokens move to their own table.", "created_at": "2026-02-05T12:00:00Z", "uid": "synthetic:comment:2", "url": "https://example.com/synthetic/app/pull/1#comment-2", "work_item_uid": "synthetic:pr:1"}
{"author_login": "erin", "body": "Rounding is off by a cent for annual plans.", "created_at": "2026-03-06T12:00:00Z", "uid": "synthetic:comment:3", "url": "https://example.com/synthetic/app/pull/3#comment-3", "work_item_uid": "synthetic:pr:3"}
```

## `ownerships.jsonl` → Ownership

Declared ownership (like CODEOWNERS). Leave `systems` empty to map `pattern` through the path rules.

| field | type | required |
|---|---|---|
| `owner_kind` | `person` / `team` | yes |
| `owner` | str | yes |
| `pattern` | str | yes |
| `systems` | list[str] |  |

```json
{"owner": "identity", "owner_kind": "team", "pattern": "/services/auth/", "uid": "synthetic:codeowners:1", "url": "https://example.com/synthetic/app/blob/main/CODEOWNERS"}
{"owner": "payments", "owner_kind": "team", "pattern": "/services/billing/", "uid": "synthetic:codeowners:2", "url": "https://example.com/synthetic/app/blob/main/CODEOWNERS"}
{"owner": "identity", "owner_kind": "team", "pattern": "/web/", "uid": "synthetic:codeowners:3", "url": "https://example.com/synthetic/app/blob/main/CODEOWNERS"}
```

## `links.jsonl` → Link

Typed edges between records that already exist. Allowed combinations are listed below.

| field | type | required |
|---|---|---|
| `rel` | `CLOSES` / `MENTIONS` / `PART_OF` / `MEMBER_OF` / `BLOCKS` | yes |
| `from_uid` | str | yes |
| `from_label` | `Person` / `Team` / `System` / `Change` / `WorkItem` / `Document` | yes |
| `to_uid` | str | yes |
| `to_label` | `Person` / `Team` / `System` / `Change` / `WorkItem` / `Document` | yes |
| `props` | dict[str, str or int or float or bool] |  |

```json
{"from_label": "Person", "from_uid": "person:alice", "rel": "MEMBER_OF", "to_label": "Team", "to_uid": "team:identity"}
{"from_label": "WorkItem", "from_uid": "synthetic:pr:1", "rel": "CLOSES", "to_label": "WorkItem", "to_uid": "synthetic:issue:11"}
{"from_label": "Change", "from_uid": "synthetic:commit:a001", "rel": "PART_OF", "to_label": "WorkItem", "to_uid": "synthetic:pr:1"}
```

### Allowed links

| rel | from | to |
|---|---|---|
| BLOCKS | WorkItem | WorkItem |
| CLOSES | WorkItem | WorkItem |
| MEMBER_OF | Person | Team |
| MENTIONS | Document | System |
| MENTIONS | Document | WorkItem |
| MENTIONS | WorkItem | System |
| MENTIONS | WorkItem | WorkItem |
| PART_OF | Change | WorkItem |

`BLOCKS` runs from the blocking item to the blocked one.

A `MENTIONS` link from a WorkItem to a WorkItem may name its target by URL instead of by uid:
`"to_uid": "url:https://github.com/acme/app/pull/12"`. The loader matches it to the work item
whose `url` is that address, so a ticket can point at a PR the source has no uid for. This is the
only link where a `url:` target is accepted, and a `url:` ref is never a `from_uid`.

Relationship types and labels cannot be Cypher parameters, so each combination has its own
load query (`queries/load/link_*.cypher`). A link whose end node is not in the graph is
dropped and counted in the ingest summary.
