# Keeper Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the Keeper. It turns failed questions and noticed problems into gaps, consults `pm`
and `qa`, and writes checked claims into the brain. Sources always win, critical updates wait
for a lead, and every action is logged.

**Architecture:**
- **Ledger.** It lives in its own graph `keeper_<slug>` and survives rebuilds. The agents reach it
  through a `WorkStore`-shaped store with two implementations: FalkorDB and in-memory.
- **Projection.** Accepted claims are copied into `brain_<slug>` as `Claim` nodes through named
  queries in `brain/keeper.py`.
- **Jobs.** The new jobs (`keeper.decide`, `pm.consult`, `qa.consult`, `pm.follow_up`) run through
  the existing `runner.run_job`. A bounded review run orchestrates them.
- **Backend.** It starts reviews after builds and on demand, and serves the approve/reject and log
  routes.

**Tech Stack:** Python 3.12 (uv workspace), FalkorDB (named `.cypher` files), the anthropic SDK
through `agents/loop.py`, FastAPI with SSE, SvelteKit 5.

**Spec:** `docs/superpowers/specs/2026-10-16-keeper-design.md`. Read it first; this plan argues from it.

## Global Constraints

- Dependency rule backend → agents → brain. `apps/brain/tests/test_package_boundaries.py` must pass.
  Only `brain/db.py` creates connections. Agents select other graphs through `db.client()`, as
  `agents/checkpoint.py` does.
- Python never holds Cypher. Every query is a `.cypher` file with a `// purpose / params / returns
  / example` header, loaded by `queries.get(name)`. Ledger queries go in
  `apps/brain/queries/ledger/` and run on `keeper_<slug>`. Brain-side Keeper queries go in
  `apps/brain/queries/keeper/` and run on `brain_<slug>`.
- **Sources win.** A claim that contradicts an ingested fact becomes `conflicts_with_source`, is
  never projected, and skips approval.
- **Nothing is deleted.** Claims are superseded (`valid_to` set), marked stale, rejected or
  conflicted. Gaps are resolved or dismissed. LogEntries are append-only.
- **"Critical" is a fixed rule in code.** Reasons: `replaces_claim`, `high_impact_system`,
  `no_source_evidence`.
- Every new job has an offline policy in `agents/policies`. `make test` makes no API calls. Graph
  tests use throwaway graphs `test_<hex>` and skip when FalkorDB is down (`brain.testing.falkordb_up`).
- Budgets: review on demand `KEEPER_BUDGET=5`; after a build `KEEPER_BUILD_BUDGET=3`. Noticing adds
  at most `KEEPER_NOTICE_CAP=10` new gaps per run. A gap gets `attempts` ≤ 2, then becomes `needs_person`.
- Settings live in `brain/config.py` (`Settings`, env vars). Ruff, line length 100.
- UI: every Keeper screen goes through the `/design-directions` skill (mockups, then the user's pick)
  before any Svelte code. Components read tokens only (`apps/frontend/design-system.md`).
- Base branch `main`. Branch `feat/keeper` (worktree `.claude/worktrees/keeper`).

## Review Focus

1. **A rebuild deletes `brain_<slug>` mid-review.** The review must stop with `stop="brain_unavailable"`,
   leave the ledger consistent and log the stop. It must not crash the backend thread. (Task 9)
2. **Double-click approve.** Approving the same claim twice, or approve and reject racing: exactly
   one wins. The loser gets `ClaimNotPending` → HTTP 409, and only one log entry is written. (Tasks 8, 11)
3. **The same question asked differently.** "Who owns Billing?" and "who owns billing" make one gap
   with `count == 2`, not two gaps. (Task 6)
4. **Evidence that vanished.** A claim cites a uid the run saw, but a rebuild removed it before the
   check. The claim is rejected (`evidence_missing`), the gap's `attempts` goes up, and it is logged. (Task 8)
5. **Sources changed before approval.** A claim waiting for approval that the sources now contradict
   becomes `conflicts_with_source` when the lead approves it. It is never projected. (Task 8)

  - `ledger/open_gap` `{uid, kind, text, norm, subject, about, trace_id, now}` → `[{uid, created: bool,
    count}]`. Dedupe: an existing gap with the same `kind` and (`norm`, or `subject` for noticing
    kinds) in status `open`/`in_review` gets `count+1`, `trace_ids += trace_id`, and keeps its
    `uid`. Otherwise a new gap is created.
  - `ledger/gaps` `{statuses: list[str], limit}` → Gap rows, newest `updated_at` first.
  - `ledger/set_gap_status` `{uid, from: list[str], to, reason, now, attempts_inc: 0|1}` →
    `[{uid, status}]`. It is guarded: an empty result means the gap's status was not in `from`.
  - `ledger/log` `{uid, at, actor, action, why, gap, claim, evidence}` → `[{uid}]`.
    `ledger/read_log` `{limit, gap?, claim?}` → newest first.
  - `ledger/review_start` `{uid, trigger, budget, now}` → `[{uid}]`, only when no review is
    `running`. `review_finish` `{uid, state, stop, now}`. `review_current` `{}` returns the latest.
    `review_stop_running` `{now}` sets every running review to `stopped` (used on restart).
  - `work/write_episode` and `memory/write_episode` (called by `runner.run_job`) are accepted by both
    stores and stored as a LogEntry with `action="episode"`, `why=summary`, `actor=agent`.

**Files:**

**Interfaces:**
- Produces, in `brain.keeper`, all on `brain_<slug>`:
  - `evidence(slug: str, uids: list[str]) -> dict[str, str]`, mapping uid to label for the uids
    that exist.
  - `source_facts(slug: str, subject: str) -> SourceFacts`. `SourceFacts` is a dataclass:
    `exists: bool, declared_owners: list[str], top_expert: str | None`.
    - `declared_owners` are the person and team uids that `OWNS` the system.
    - `top_expert` is row 0 of `tools/experts_for_system` for that system, or None if the subject
      is not a System.
  - `high_impact_systems(slug: str) -> set[str]`. Systems are ranked by the number of distinct
    systems that co-change with them. The result is the top `ceil(n * 0.25)` systems with at least
    one partner; ties at the cut are included.
  - `project(slug: str, claims: list[dict]) -> list[str]`. It `MERGE`s
    `(:Claim {uid, kind, subject, title: statement, statement, value, status:'accepted',
    valid_from, author, approved_by})` with `ABOUT` edges to the about uids and `EVIDENCE` edges to
    the evidence uids. It returns the uids of claims whose subject or every evidence uid is
    missing. Those are not projected.
  - `retire(slug: str, uid: str, status: str, valid_to: str) -> None` sets the projected claim's
    `status` and `valid_to`. Nothing is deleted.
  - `notice(slug: str, kind: str, limit: int) -> list[dict]` returns rows
    `{subject, about: list[str], text}` for `stale_owner` (from the `owners_vs_experts` logic) and
    `unowned_hot_system` (systems with activity in the last 90 days and no `OWNS`).
- Tool `keeper_notes`:
  - Params `{uid: str}`.
  - Rows are `{uid, kind, statement, value, valid_from, approved_by, evidence: [{uid, label, title,
    url}]}`: the accepted claims `ABOUT` that uid with `valid_to IS NULL`.
- `system_prompt.md`, one static rule: "Answer from the sources first. Use Keeper notes
  (`keeper_notes`, `Claim` neighbours) only for what the sources don't say, and say that this
  part comes from the Keeper."

### Task 6: Gaps from Ask traces and thumbs

**Interfaces:**

**Files:**

**Interfaces:**
- Produces:
  - `class BrainFacts(Protocol)`: `evidence(slug, uids)`, `source_facts(slug, subject)`,
    `high_impact_systems(slug)`, `project(slug, claims)`, `retire(slug, uid, status, valid_to)`.
    The default is the `brain.keeper` module.
  - `class ClaimNotPending(Exception)`.
  - `apply_decision(store: WorkStore, ctx: Ctx, gap: Gap, sub: SubmitKeeperDecision, brain:
    BrainFacts = brain.keeper) -> list[Row]` runs these steps in order:
    1. `dismiss` → gap `dismissed`, logged `gap_dismissed`. `needs_person` → gap `needs_person`,
       logged.
    2. `evidence` check:
       - any cited uid missing → the claim is written `rejected` with `why="evidence_missing: <uids>"`;
       - the gap goes `in_review` → `open` with `attempts_inc=1`, or to `needs_person` when attempts
         reach 2;
       - logged `claim_rejected`. (Review Focus 4)
    3. `conflict(...)` → the claim is written `conflicts_with_source`, `conflict=<text>`, not
       projected; the gap is `resolved`; logged `claim_conflicts_with_source`.
    4. `critical_reasons(...)`:
       - non-empty → `pending_approval`; the gap stays `in_review`; logged `claim_queued`;
       - empty → `accept`.
  - `accept(store, ctx, claim: Claim, by: str, brain) -> Claim`:
    - any accepted claim with the same kind and subject → `superseded`, `valid_to=now`,
      `brain.retire`, logged `claim_superseded`;
    - then `accepted`, `brain.project([claim])`;
    - if projection reports it missing → `stale` (logged `claim_stale`) and the gap reopens;
    - else the gap is `resolved`, logged `claim_written` (`actor` = by, or `"auto"`).
  - `approve(store, slug, claim_uid, by, why, brain) -> Claim`:
    - the claim must be `pending_approval`, else `ClaimNotPending`;
    - re-run `conflict` with fresh `source_facts`: now conflicting → `conflicts_with_source`
      (Review Focus 5); otherwise `accept`;
    - logged `claim_approved` with `actor=by`.
  - `reject(store, slug, claim_uid, by, why) -> Claim`:
    - the guarded status write → `rejected`;
    - the gap → `open`, `attempts_inc=1` (→ `needs_person` at 2);
    - logged `claim_rejected` with `actor=by`.

    one wins; the other raises `ClaimNotPending`. (Review Focus 2)

**Files:**

**Interfaces:**

    - for each kind in `("stale_owner","unowned_hot_system")`, take `brain.notice(slug, kind, cap)`;
    - skip subjects that have an accepted claim of the matching kind (`owner` for both) or an open
      follow-up for such a claim;

    - log `gap_opened` for each new one;

    - re-check `conflict` → `superseded`, logged `claim_superseded` with `why="source: <text>"`;
    - otherwise project it, and mark the claims reported missing `stale` (their gap reopens).
  - `ReviewEvent`: a dataclass with `kind: Literal["start","step","done","stopped","failed","skipped"],
    step: str | None, gap: str | None, claim: str | None, message: str`.

    3. Pick `budget` open gaps with `pick_order` and set each to `in_review`.
    4. Post consults for `pm` and `qa`, then run each consult job with `runner.run_job(...,
       client=client_for(role, job))`.
    5. Run `keeper.decide` per gap.
    6. Run `pm.follow_up` over `ledger/queue_follow_up` (all, not budgeted).
    7. `review_finish("done")`.
    - `should_stop()` is checked between jobs → `stopped`.
    - A FalkorDB `ResponseError` or a missing brain graph (`db.graph_exists` False) → `stopped`
      with `stop="brain_unavailable"`. (Review Focus 1)
    - Any other exception → `failed`, with its message in `stop`.
    - Every step emits a `ReviewEvent`; every end writes a LogEntry `review_<state>`.
  - `budget=0` runs only steps 1, 2, 6 and 7. The backend uses this after an approval, so the PM
    follow-up appears.

    pass `policies.offline_client`.
